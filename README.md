# Лабораторна робота №2 "CI/CD та ML API"

[![CI](https://github.com/Failara/MLOPs-Course/actions/workflows/ci.yml/badge.svg?branch=Lab2)](https://github.com/Failara/MLOPs-Course/actions/workflows/ci.yml)

## Опис проєкту

Цей проєкт демонструє побудову наскрізного MLOps-конвеєра для простої моделі машинного навчання. Він включає написання скрипта для тренування базової ML-моделі класифікатора Iris, розробку REST API за допомогою FastAPI, покриття логіки unit-тестами, повну контейнеризацію застосунку через Docker, налаштування безперервної інтеграції (CI) за допомогою GitHub Actions та публічне розгортання готового сервісу на хмарній платформі Render.

## Стек технологій

Проєкт побудовано з використанням мови програмування Python. Для завдань машинного навчання використовується бібліотека scikit-learn, а для серіалізації та збереження навченої моделі — joblib. Веб-сервіс реалізовано на базі високопродуктивного асинхронного фреймворку FastAPI та сервера Uvicorn. Валідація вхідних даних здійснюється за допомогою схем Pydantic. Тестування коду та кінцевих точок забезпечується фреймворком pytest разом із тестовим клієнтом httpx. Інфраструктурна частина покладається на Docker для ізоляції середовища, GitHub Actions для автоматизації тестування при кожному оновленні коду та платформу Render для фінального хостингу.

## Як запустити локально

Для локального запуску та тестування системи спочатку необхідно клонувати репозиторій на свій комп'ютер та перейти у створену директорію. Після цього створюється та активується ізольоване віртуальне середовище Python. Наступним кроком є встановлення всіх необхідних залежностей за допомогою команди `pip install -r requirements.txt`. Перед запуском сервера обов'язково треба натренувати модель, виконавши команду `python -m ml.train`, щоб згенерувати артефакт `model.joblib`. Зрештою, локальний сервер запускається командою `uvicorn app.main:app --reload`, після чого інтерактивна документація API буде доступна у браузері за адресою `http://localhost:8000/docs`.

## Запуск через Docker

Для швидкого запуску сервісу в ізольованому контейнері без налаштування локального Python-середовища використовується Docker. Спочатку збирається образ із тегом `ml-api:lab2` за допомогою команди `docker build -t ml-api:lab2 .`. Цей процес також автоматично тренує модель всередині контейнера. Після успішної збірки контейнер запускається командою `docker run --rm -p 8000:8000 ml-api:lab2`. Сервіс буде доступний локально на порту 8000.

## Як запустити тести

Усі автоматизовані перевірки ізольовані та знаходяться у директорії `tests`. Для їх виконання достатньо запустити команду `python -m pytest -q` у кореневій директорії проєкту. Система автоматично знайде та виконає перевірки для скрипта тренування моделі та всіх кінцевих точок API, гарантуючи їхню коректну роботу перед розгортанням.

## Як працює API

REST API надає три основні кінцеві точки. Кореневий шлях `/` використовується для базової перевірки та повертає інформацію про назву сервісу. Шлях `/health` виконує роль "liveness probe" і використовується для перевірки статусу системи та підтвердження того, що файл моделі успішно знайдено та завантажено в пам'ять. Головний метод `/predict` приймає POST-запити у форматі JSON із чотирма фізичними параметрами квітки (sepal_length, sepal_width, petal_length, petal_width) та повертає ідентифікатор передбаченого класу, назву виду квітки та ймовірність передбачення.

## Структура репозиторію

Кодова база проєкту має логічне розділення на компоненти для зручності підтримки. Директорія `app` містить основний код веб-сервісу `main.py` та схеми валідації даних `schemas.py`. Директорія `ml` відповідає за логіку машинного навчання і містить скрипт для тренування `train.py`. У директорії `tests` знаходяться файли з unit-тестами. Конфігурація для автоматизації GitHub Actions розміщена за шляхом `.github/workflows/ci.yml`. У корені проєкту також знаходяться інструкції `Dockerfile` та `.dockerignore`, перелік залежностей `requirements.txt` та згенерований артефакт навченої моделі `model.joblib`.
