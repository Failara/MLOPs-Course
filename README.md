# Лабораторна робота №3: Моніторинг ML API та детекція проблем

## Опис системи

У цій роботі реалізовано повноцінну систему моніторингу для існуючого ML-сервісу класифікації ірисів. Архітектура включає оновлений FastAPI-додаток, який інтегровано з Prometheus для збору метрик інференсу. Додано компонент для статистичного виявлення зсуву даних за допомогою критерію Колмогорова-Смирнова та налаштовано генерацію детальних візуальних HTML-звітів через бібліотеку Evidently. Вся інфраструктура запакована у Docker Compose для зручного розгортання.

## Реалізовані метрики

Система збирає декілька ключових метрик для спостереження за станом сервісу. Лічильник ml_predictions_total фіксує загальну кількість прогнозів із розбиттям за класами. Гістограма ml_prediction_latency_seconds вимірює час обробки кожного запиту. Гістограма ml_prediction_confidence відстежує розподіл ймовірностей передбачень моделі. Також реалізовано лічильник ml_errors_total для фіксації помилок, датчик ml_model_loaded для відображення статусу завантаження моделі та лічильники перевірок зсуву даних ml_drift_checks_total і ml_drift_detected_total.

## Drift detection

Виявлення зсуву даних реалізовано за допомогою двовибіркового тесту Колмогорова-Смирнова. Під час запуску сервіс завантажує еталонну вибірку, на якій тренувалася модель. При надходженні нових даних через ендпоінт /check-drift система порівнює їх розподіл із еталонним для кожної ознаки. Якщо p-value виявляється меншим за встановлений поріг значущості alpha, сервіс сигналізує про виявлення зсуву та оновлює відповідні метрики у Prometheus. Для більш глибокого офлайн-аналізу застосовується відкрита бібліотека Evidently.

## Приклади запитів

Для перевірки здоров'я сервісу використовується GET-запит на маршрут /health. Звичайний інференс виконується через POST-запит на маршрут /predict із передачею JSON-об'єкта, що містить чотири числові параметри квітки. Для ручної перевірки зсуву даних відправляється POST-запит на маршрут /check-drift, де у тілі передається масив samples із набором спостережень та необов'язковий параметр alpha. Збір метрик системою Prometheus здійснюється через автоматичні GET-запити до маршруту /metrics.

## Логування

Сервіс використовує структуроване логування у форматі JSON за допомогою бібліотеки python-json-logger. Це дозволяє легко інтегрувати логи з сучасними системами агрегації, такими як ELK або Grafana Loki. Кожен лог містить точну мітку часу, рівень важкості, назву логера та детальний контекст події, наприклад, вхідні параметри, результат прогнозу та ймовірність для кожної успішної операції.

## Як запустити моніторинг

Для запуску всієї інфраструктури моніторингу необхідно перейти до директорії monitoring та виконати команду docker compose -f docker-compose.monitoring.yml up --build. Це підніме два контейнери: сам веб-сервіс із моделлю та сервер Prometheus, налаштований на збір метрик кожні 10 секунд. Після успішного запуску веб-інтерфейс Prometheus буде доступний у браузері за адресою localhost:9090, де можна виконувати запити мовою PromQL та будувати графіки.

## Висновки

У результаті виконання роботи було успішно впроваджено практики нагляду за моделями машинного навчання. Налаштовано збір бізнес-метрик та системних показників, реалізовано автоматичне виявлення деградації вхідних даних та забезпечено структуроване збереження історії подій. Це перетворює звичайний скрипт на надійний сервіс, готовий до експлуатації у виробничих умовах.
